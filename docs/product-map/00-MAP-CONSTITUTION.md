# Newsroom Product Map Constitution

Newsroom will not discover the product one page at a time.

A Newsroom surface exists because a reporter needs to perceive, retrieve, verify, organize, decide or act on reporting reality. A table, route or feature request does not by itself justify a screen.

## Mapping sequence

```text
System reality
→ Encounter justification
→ Screen identity
→ Screen purpose
→ Required orientation
→ Primary information
→ Interaction
→ Decision meaning
→ State mutation
→ Next state
→ Empty / partial / error behavior
→ Implementation
```

## Governing rules

1. **Reality before feature.** Build the reporting reality the feature is supposed to expose.
2. **Evidence is not interpretation.** Machine transcript, AI summary and reporter judgment stay distinguishable.
3. **Every screen belongs to one newsroom.** Do not create mini-apps with independent interaction languages or identity roots.
4. **No interaction remains undefined.** If we cannot answer exactly what happens after an action, the screen is not ready.
5. **Unknown is a designed state.** Missing speaker identity, incomplete processing, unresolved source relation and conflicting reporting remain explicit.
6. **Visible evidence is reachable.** A quote, speaker, source, topic or timestamp should resolve back to the evidence that supports it.
7. **Information owns permanent pixels. Operations borrow pixels when invoked.** Supporting tools should not crowd the reporter's primary work surface.
8. **Capture first; organize second.** A recording must be safely preserved even when the reporter has not yet decided what story it belongs to.
9. **Collection is not storage custody.** A reporting Collection groups related evidence through Topic relationships; it does not move or own the source.
10. **Search and capture are distinct.** Search retrieves existing evidence. Upload/recording introduces new evidence.

## Fixed screen template

Every mapped screen records:

1. Screen ID
2. Name
3. Status
4. Purpose
5. Audience / authority
6. Entry paths
7. Reality available on entry
8. Encounter justification
9. Required orientation
10. Primary information
11. Interactions
12. Decision meaning
13. State mutation
14. Next states
15. Back / exit behavior
16. Permissions
17. Provenance / explanation
18. Empty state
19. Uncertain / partial state
20. Loading / processing state
21. Error / conflict state
22. Correction / undo
23. System dependencies
24. Open questions
25. Exit criteria
